# Phase 1 walk: two phones (SPEC:R100)

Walked 2026-11-23 on a OnePlus 6T (Android 11, English) and a OnePlus 9 Pro (Android 14, Italian), with
the debug build of branch `phase-1-t15-16`. The phones were driven over adb, by tapping elements found by
their text. The data was invented and the test passphrase was made for the walk.

## Setup

- **Shared folder:** `Documents/MedicAll-test`, shared between the two phones by Syncthing-Fork. The
  owner set up the share.
- **Backup folder:** `Documents/MedicAll-backup-test` on each phone, not shared.
- **Picker:** the harness opens it at the right folder (`EXTRA_INITIAL_URI`), because DocumentsUI on
  the 6T ignores adb taps on its folder rows. Its buttons ("Use this folder", "Allow") take them.

## Found and fixed during the walk

- **Unlocking crashed on Android 11.** `DeviceId` called `Files.writeString`, which Android adds only in
  API 33. It now calls `Files.write`. The desktop tests run on Java 21 and could not catch this, and
  Android Lint does not analyse the multiplatform shared code even with `checkDependencies`. Only a
  device run finds this kind of defect.
- **The phone's password manager offered autofill on the test passphrase field.** The harness field is
  now excluded from autofill.

## Left as it was

- **Test data on the phones:** MedicAll's data was cleared on both phones after the walk. The shared test
  folder and the two backup folders are left for the owner to remove, along with the Syncthing share.
- **What the walk did not cover:**
  - Android's Auto Backup, which is off;
  - a provider that cannot rename;
  - a 16 KB page device;
  - the minified release build.
